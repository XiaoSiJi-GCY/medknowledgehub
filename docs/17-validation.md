本记录对应 2026 年 10 月 22 日的本机验证。验证的目标是确认代码链路、依赖连接和接口行为。复现时应同时记录模型、资料版本、测试集及环境，模型回答和耗时可能变化。

## 2. 程序行为测试

执行 `python -m pytest -q`，结果为 **30 passed**。`ruff check .` 和两个虚拟环境中的 `pip check` 通过。

测试覆盖实际文件解析、数据库事务、权限范围、版本发布、失效资料、缓存授权、SQL AST 校验、引用检查、工作流循环上限、HTTP/SSE 和进程内 MCP 调用。模型与外部索引在这组测试中使用受控替身，以便稳定构造失败条件；不能据此推导真实模型效果。具体断言位于 `tests/`，对应业务实现见 [源码目录](source-tree.md)。

## 3. 真实系统联调

`python -m scripts.smoke_live` 使用真实 HTTP、Celery、四个基础服务和模型 API，九项检查通过：

| 检查 | 验证内容 |
| --- | --- |
| 异步入库与检索 | 上传资料后由 Worker 完成解析、向量与图索引，能检索到证据 |
| 版本切换 | 新版本发布后只返回当前可用版本的资料 |
| 跨空间访问 | 另一空间无法读取受限知识库及原文 |
| 删除与归档 | 删除资料或归档知识库后不再参与问答 |
| 混合问答 | 使用真实向量、BM25 与重排链路回答并返回引用 |
| 图关系问答 | 查询来源约束下的关系与路径 |
| 结构化问答 | 执行受控 SQL，正确取得科室目录数量 |
| CarePilot 接口契约 | 适配接口返回约定字段，服务身份权限生效 |
| SSE | 收到工作流进度、答案内容和完成事件 |

报告位于 `artifacts/smoke-live.json`。脚本创建独立回归空间，完成后归档其资料；不会覆盖初始知识库。它会消耗模型 API 用量。

额外完成一次真实队列重建索引：原版本继续可读，替代版本构建完成后发布。Streamlit AppTest 连接真实 API，完成管理员登录、发送问题、接收 SSE 与展开证据，未出现页面异常。

## 4. 初始资料与评测结果

初始资料包括四份有公开来源链接的中文阅读笔记和一份结构化科室目录，来源清单在 `data/source_manifest.json`。这五份资料用于理解完整链路；阅读笔记并非官方中文版临床指南。目录包含六条科室记录，不包含实时医院排班。

评测集 `evals/datasets/retrieval.jsonl` 共八题，其中七题有相关资料标注，一题为资料不足。检索相关性按**文档标题**标注与去重，不是逐片段的医学相关性标注。

| 本次运行 | 结果 | 解释范围 |
| --- | --- | --- |
| rerank | Recall@K、MRR、nDCG 均为 1.0 | 七条正例，在当前小语料与文档级标注下计算 |
| agentic | 上述三项均为 1.0，路线正确率与无答案判断正确率均为 1.0 | 八题；不能代表开放医疗问题的正确率 |
| RAGAS Faithfulness | 七条有依据回答的平均值 0.90 | 模型判断回答与检索上下文的一致性，不是临床准确率 |

RAGAS 逐题值为 1、1、1、1、1、0.8、0.5。后两题涉及科室目录与聚合查询，应对照真实 SQL 结果、来源上下文和回答逐条审查。不能仅依赖平均值评价系统。当前生成模型与判断模型相同，也存在共同偏差。

本次 rerank 的端到端延迟 p50 约 1.32 秒、p95 约 1.56 秒；agentic 约为 16.23 秒和 45.88 秒。八题样本很少，缓存、模型排队与检索轮次会影响耗时，不能作为服务承诺或并发容量结论。

报告位于 `artifacts/evals/rerank.json`、`agentic.json`、`ragas.json`。指标实现、复现命令及后续扩充方法见 [评测文档](13-evaluation.md)。

## 5. 容器验证

应用 Docker 镜像构建成功。在该镜像内执行 `scripts.check_environment`，PostgreSQL、Redis、Neo4j 和 Milvus 均返回 ready。另在容器中读取本机已入库文档，确认 Windows 与 Linux 共用 `data/` 时可以定位原始文件。

本次页面、API 和 Worker 主要运行在本机 Python 环境；容器验证覆盖构建、依赖连接及共享文件读取。完整容器部署命令位于 [运行手册](02-quickstart.md)，启动前应停止占用 8010、8510 的本机进程。

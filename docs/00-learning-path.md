# 学习路线：从第一次运行到独立解释源码

本项目文档面向已经学过 Python、LangChain，正在学习 LangGraph 的读者。建议先建立一条请求的直觉，再学习各个存储组件。无需先通读全部源码。

## 第一阶段：完整使用一次

按 [快速开始](02-quickstart.md) 启动服务，登录管理员账号。在“资料与版本”查看已有任务和文档，询问“咳嗽持续超过三周怎么办”，展开引用，再到“检索检查与反馈”看召回和排序。观察问题、证据、回答之间的区别。

完成标准：知道 API 的 8010 端口和页面的 8510 端口各自做什么；能找到一条回答的具体原文，能说明当前资料规模。

## 第二阶段：沿请求读代码

依次打开 `app/main.py`、`app/api/routes.py`、`app/services/answers.py`、`app/agents/state.py`、`app/agents/graph.py`。跟踪 `/answers` 怎样校验身份、获取可读范围、执行图、保存查询记录。

练习：在纸上画出一次成功检索与一次证据不足的路径。解释为什么只有证据不足且未到上限时才走 `retry`。不要把每个节点都理解成一次模型调用。

## 第三阶段：理解入库与检索

阅读 [入库](04-ingestion.md) 与 [混合检索](06-hybrid-retrieval.md)。用一份自己制作的两页 PDF 入库，检查页码和 bbox。再上传修改版，观察版本切换和旧内容的排除。

完成标准：能解释 Chunk、父上下文、Dense、BM25、RRF、Reranker 的不同职责；知道版本发布为什么放在外部索引写入之后。

## 第四阶段：理解权限、图和 SQL

创建一个 viewer 成员和受限知识库，分别验证授权前、授权后、撤权后的行为。然后查看 [GraphRAG](08-graph-rag.md) 的参数化路径模板与 [SQLRAG](09-sql-rag.md) 的 AST 重写。

完成标准：知道 tenant_id 由服务端身份得到；能解释为什么向量过滤之后仍需要回到 PostgreSQL 校验；能指出 SQL 查询实际访问的权限子查询。

## 第五阶段：验证与面试表达

运行测试，再运行真实服务验证和一组检索消融。阅读报告里的失败案例与口径。沿 [面试导读](16-interview-guide.md) 自问：为什么用四种数据服务？为什么不是每个问题都用 HyDE？引用检查能证明什么、不能证明什么？

建议每读完一章完成该章实验，再用自己的话解释两分钟。学习目标是能修改一个模块、验证行为变化，并清楚说明结果的适用范围。

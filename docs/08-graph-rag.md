# GraphRAG：有出处的实体关系查询

实现位于 `clients/models.py` 的 `extract_edges()` 和 `storage/graph.py` 的 `GraphIndex`，在线入口是 `Retriever.graph()`。

## 图怎样建立

入库时按 Chunk 抽取 source、target、relation 和 quote。实体名称与引文必须逐字出现在当前原文；关系只允许固定类型。每条边携带 tenant_id、kb_id、document_id、version_id 与 chunk_id，实体 key 包含空间和知识库，避免不同知识空间串图。

字符串存在检查可以剔除一部分编造实体，但不能证明抽取关系在医学语义上正确。当前图关系是原文抽取的候选关系，不是经专家审核的临床知识图谱。

## 查询怎样执行

问题中的实体或原始查询用于匹配起点，Neo4j 使用固定参数化 Cypher 模板执行最多三跳路径。每个节点与每条边都必须满足空间、知识库和当前有效版本条件。路径最终转换回原文 Chunk，回到 PostgreSQL 再次校验后供回答引用。

项目没有让模型自由生成和执行 Cypher。路径中的关系文本可以在 debug.paths 检查，最终结论仍引用文档片段。

## 动手学习

在页面明确选择“图关系检索”，询问带状疱疹与皮疹、水疱的关系。观察实体路径和原文出处；然后停用对应文档，确认旧关系不再参与结果。`test_rag.py` 覆盖路径与来源绑定；真实服务验证由 `scripts.smoke_live` 覆盖。

边的方向、关系抽取质量、实体别名和路径相关性仍需更大规模标注评测。初始语料只能展示链路，不能证明多跳医学推理能力。
